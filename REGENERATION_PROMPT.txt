RECRUITS: RTS CAMERA / COMMANDER - REGENERATION CONTEXT
Current source version: 0.12.1-server.1
Minecraft/loader: Forge 1.20.1, Forge 47.2.0
Base dependency: Villager Recruits 1.15.2. Formation geometry, slot execution and tactical navigation are native to this mod. Freecam is bundled as a compile dependency. Order Relay, Serious Player Animations, Siege Weapons and Small Ships integrations must remain optional.
VERSION POLICY: Every source behavior change must increment the semantic version in gradle.properties. Use a patch increment unless the change adds a backward-compatible feature (minor) or breaks compatibility (major), and keep CHANGELOG.txt, BUILD.bat, the debug HUD and this file synchronized.

PROJECT GOAL
Turn Recruits combat into a Total War: Rome II-like RTS commander mode while preserving normal Minecraft outside RTS. Server authority and 100v100+ reliability matter more than flashy hacks. Use native Recruits mechanics where practical, but Commander may override broken attack/formation behavior.

0.12.1 HEADLINE CHANGES (CURRENT)
- Better Formations is no longer a dependency. NativeFormationController owns preset/frontage/freehand slot assignment, shared group routes, laggard catch-up, custom-slot persistence and movement authority. Laggards accelerate and replan individually; they never stop the shared anchor. Moving slots bypass stationary locking so formations do not pulse between stop and start. Native Recruits formation commands enter the same runtime; ordinary Recruits move/follow/attack/upkeep orders release that authority.
- TacticalPathfinder is a collision-shape A* over actual support surfaces. It rejects unsupported air, handles slabs/stairs/modded shapes, creates ladder links and marks narrow/elevated routes for single-file dispersed transit. Formations remain dispersed through partial replans and reform only at the destination. Terrain-region revisions invalidate affected routes.
- RecruitRuntimeBrain/Registry, RecruitSpatialIndex and RecruitAIScheduler provide transient orthogonal state, event-maintained lookup, local separation and bounded formation/recovery path work. Goal mixins enforce one movement authority while the formation runtime is active. These systems do not implement simulation or rendering LOD.
- ProjectileAwarenessManager records hostile projectile corridors and impacts by formation. ShieldTactics uses this event-driven alert to raise available shields and face horizontal fire; descending fire selects the existing UP interception posture.
- Book/Tactics & Abilities remains on the command bar; the dedicated Charge button was removed. Double-RMB the same enemy formation to charge. Group Charge skips formation staging; foot melee receives a temporary +20% speed for eight seconds. Ranged troops remain ranged unless Melee mode is chosen.
- New TacticalSettings stores per-group Native/Ranged/Melee choice, Skirmish, Native/Front/Up/Auto shield mode and Hold Fire. RTSGroupTacticsSavedData keeps legacy Use Missiles intact, saves new settings and ability timers, and reads entries independently so one damaged entry does not discard other groups.
- New server-validated TacticsControlPacket and owner-only TacticsStateSyncPacket. ClientTactics is reset on logout. Network protocol rts-camera-120 requires clients and server to update together.
- SkirmishController temporarily owns movement while closing or retreating; native ranged goals fire in the useful range band. Foot retreat thresholds: enter <8 blocks, release >=14; horse archers <12/>=20. Foot advance >27/stop <=21; mounted >32/stop <=25. Retreat direction commits during each withdrawal. Path and local-threat checks occur at bounded intervals. This is not morale routing and never disbands/removes soldiers.
- Ranged/Melee preferences are respected during persistent attack refresh. Melee can swap a bow/crossbow for an available carried sword, axe, trident or #throwable_weapons item via the native inventory swap API. Do not create a missing backup weapon. Hold Fire persists, blocks new recruit projectile spawns, prevents Commander throw wind-up/release and is respected by Strategic Fire.
- Dismount cancels movement, remembers an actual horse UUID and persists RTSRemainDismounted. Mount returns to the remembered loaded horse or an eligible nearby player-owned horse using native mount navigation; no spawning/stealing/horse-teleport. Horse checks exclude ships.
- ShieldTactics: FRONT uses ordinary directional blocking with melee threat timing; UP also intercepts descending arrows/Commander thrown weapons using shield durability; projectile corridor/impact events share a short alert with the formation. Piercing arrows, bypass-shield damage and native shield cooldown remain respected. Food/potions/active ranged use take precedence.
- RecruitShieldMixin disables native UseShield.hasShieldInHand only while the tactical shield controller owns the stance, preventing competing raise/lower behavior. Original shield bar button returns to Native control.
- IMPORTANT: UP currently uses the normal native blocking pose. Dedicated overhead visuals remain a separate animation-addon task. RTSShieldUp and RTSTacticalShield are server persistent runtime flags, not a completed SPA animation integration.
- Second Wind: remove 25 fatigue, group cooldown 60 seconds. Hold the Line: halve Commander-applied morale shocks for 15 seconds, group cooldown 60 seconds. War Cry: -8 morale to visible hostile formations within 18 blocks, group cooldown 90 seconds; each victim formation can receive only one cry shock per ten seconds. Timers persist. No ability can rally a routed group.
- ProjectileBalance adds armor-sensitive damage for recruit-fired arrows and Commander thrown weapons against recruits. [projectiles] defaults: arrowLightArmorDamageMultiplier=2.0, javelinLightArmorDamageMultiplier=1.6. Extra damage tapers linearly to zero at 20 armor; normal damage mitigation still follows. 1 disables each bonus.
- CavalryManeuver is a dependency-free, directly tested waypoint plan. CavalryTacticalController reserves rider AND horse movement, freezes the pass geometry through target movement/death/reassignment, exits 18 blocks beyond the impact point, turns via four points around radius 6, then accepts a fresh pass target. Members of one group turn the same way. Native terrain navigation remains the underlying pathfinder.
- Fixed 0.11.0 goal leaks/cancellation, shifting target-chase endpoints and immediate reverse turns. Cancellation removes goals and stops navigation. Blocked lanes try a turn-out then a bounded pause/replan; do not claim impassable terrain is solved.
- TacticalCombatManager enforces short-lived per-recruit target leases. Native searchForTargets is suppressed while leased and LivingChangeTargetEvent is constrained to the assigned target. Stage/engage assignments, including thrown missiles, retain formation target distribution. Routing veto wins. Expiry/Halt/replacement orders/logout/dimension changes clean up controllers.
- CHANGELOG.txt contains current behavior, caveats, controls and test results. No full Forge build or gameplay pass is claimed.

0.11.0 HISTORICAL STARTING POINT
- Introduced the mounted goal and refined frontage assignments. Its movement and lifecycle shortcomings are superseded by 0.12.0 above; do not restore the previous five hashed lane buckets, moving pass endpoint or instantaneous direction flip.

0.10.9 HEADLINE CHANGES
- Corrected the second routing failure found in playtesting: routed units no longer recompute their heading from the nearest hostile or alternate +/-60-degree stall turns. Their original outward direction is persistent, so two enemy groups cannot make them run ten blocks forward and ten blocks backward.
- Routed units no longer sprint. Foot soldiers and mounts use their normal movement speed and navigation pace during escape; the old forced 1.6 movement field and sprint flag are gone. Escape waypoints are 16 blocks and refresh every ten ticks.

0.10.8 HEADLINE CHANGES
- Fixed the user's confirmed 0.10.7 failure: routing hid the Commander card, but native Recruits retained the group and troops kept fighting. RoutedGroupManager now removes, saves and broadcasts the native group, clears all ordinary recruit AI goals and installs an exclusive escape goal. Native commands, target acquisition, morale-driven recovery and outgoing attacks are blocked while routing.
- RTSRoutingSavedData persists pending escapes independently of native groups, including unloaded roster members. Entity persistent data retains original owner/group, escape origin, direction and loaded escape time. Normal world/chunk reload must resume fleeing, never rebuild a commandable group.
- A living routed recruit must actually travel at least 30 horizontal blocks and get clear of nearby/visible hostiles before tactical removal. No automatic rally and no timed teleport. Native owner/team are retained during flight for diplomacy and campaign inspection; unit/team accounting is removed only on actual death or living escape.
- Cavalry formation targets are now 0.50 blocks/tick regular and 0.72 hasty (10 and 14.4 blocks/second before terrain/cohesion/mount armor), versus foot targets around 0.20/0.24. Mounted combat/follow navigation receives a separate temporary 1.60x mount speed multiplier, excluded during formation pacing.
- Mounted melee charges now use measured forward run-up, speed and duration. Full strength requires 22 blocks at 0.72 blocks/tick; faster/longer sustained runs produce stronger impacts up to the configured cap. The first impact has up to 48 raw bonus damage before armor/shields, then 60% and 36% for the next two contacts. Actual swept mount contact can strike the front ranks without waiting for a slow melee cooldown.
- Charge momentum is finite: at most three contacts in a short impact window; stopping, sharp turns, flight and teleport jumps cannot generate charge power. Disengagement and a fresh run-up are required for another pass. Dismounted troops, ranged projectiles and ships do not receive cavalry impact damage.
- Cavalry inflicts extra morale pressure on foot troops while dealing close-combat damage: melee 2 points/second, ranged 8. Full charge shock is up to 14 versus melee or 30 versus ranged. Pressure is per defending group; shock uses the strongest-contact budget over two seconds, not a multiplier for every horse. Existing morale-item resistance applies.
- The ten [cavalry] server config settings expose all primary speed/damage/morale defaults. Existing configs receive defaults for new keys; do not tell users to delete their configs.
- Public RoutedDesertersEvent remains intact before actual living survivors are removed. See the campaign boundary below for batch semantics.

- Morale is less brittle: routing threshold/shocks are softened and nearby living player commander supplies a modest morale-stability/recovery aura.

It exposes ServerLevel, group UUID, former owner UUID, survivor Recruit UUIDs and escape position so Settlements/campaign systems can materialize deserters/manpower/bandits. This hook is non-negotiable going forward.

BATTLE ARCHITECTURE DIRECTION
Groups should increasingly behave as persistent tactical FORMATION objects. An ATTACK order is Group/Formation A -> Group/Formation B, not a single clicked entity. Individual soldiers get stable target assignments inside the enemy formation and reassign only when their target dies/becomes invalid. This same hostile formation target should eventually drive Volley, Skirmish, Charge and other group combat behaviors.

ROUTING / CAMPAIGN BOUNDARY
Commander owns tactical route/escape. It must not silently decide campaign consequences. On successful battlefield escape it posts RoutedDesertersEvent before removing tactical entities. Settlements or another campaign layer owns whether survivors become deserters, return to manpower, form bandits, etc.
The native group is removed at initial rout, before the escape hook. The hook still exposes ServerLevel, original group UUID, original owner UUID, living survivor UUID list and escape position. Process the supplied UUID list, not a lookup of the already-removed native group. Stragglers and previously unloaded members may escape in later batches under the same original group UUID. Each living survivor is emitted once during normal save/reload operation; campaign consumers should also deduplicate by survivor UUID. Dead recruits are casualties, not deserter-event survivors. Do not turn this into a silent campaign conversion.

BASELINE IN-GAME REGRESSION CHECKS

1. Rout a fresh group while engaged. Confirm it disappears from both Commander and native Recruits command bars, stops melee/ranged attacks and cannot be recalled by native or RTS commands. Pursuers must still be able to hurt it.
2. Save/reload while soldiers are fleeing, and unload/reload a member before it has escaped. Confirm routing persists, no native group is recreated, and each living survivor exits only after traveling clear of hostiles. Verify RoutedDesertersEvent batches if a campaign consumer is installed.
3. Compare regular and hasty cavalry against light infantry over a flat, clear course, including armored riders/mounts. Cavalry should have a clear speed gap; terrain/cohesion and Armor Weight still matter.
4. Compare point-blank cavalry melee with an uninterrupted 25-30 block mounted attack into a foot formation. Front contacts should take much greater damage after the run-up, with weaker follow-through. Repeat against similarly sized melee and ranged groups; ranged morale should collapse much faster.
5. Leave cavalry bogged down in melee, then withdraw and charge again. Continued melee should apply morale pressure but no repeated full charge impacts; a new run-up should restore charge power. Also check that friendly, dismounted and ship troops receive no accidental cavalry bonus.
6. Watch routed foot and mounted units over at least 50 blocks. They should continue outward at ordinary pace without sprinting or repeatedly reversing direction. Put an enemy group on either side only as a stress test; the route should not oscillate between them.
7. Order a cavalry formation against a full enemy formation. Watch for a visible lane approach, one committed pass through the line, a turn-out beyond the enemy, and re-forming. Horses should not orbit one soldier, stop at the line, or all choose the same defender.
8. Kill or unload a defender in the middle of the fight. Its attacker should receive a replacement from the same enemy frontage before using a nearest-target fallback. Check that infantry and ranged groups also retain distributed formation target locks.
